# MobiusX Desktop implementation plan

## P0 — executable application reliability

1. **Route software builds as coding tasks** (implemented in this change).
   - Acceptance: a build-mode garden storefront mentioning images is routed as coding even when Laya says `image_generation`.
   - Evidence: targeted Laya/task tests pass; gateway TypeScript build passes.
2. **Use one reference application generated by MobiusX.**
   - Requirements: customer registration and validation, persisted submission, role-protected manager approval/rejection, status tracking, and audit history.
   - Acceptance: same persisted database record is observed through frontend/API and automated tests; negative authorization and validation cases pass.
3. **Close the first reproducible generation/runtime defect.**
   - Record the failing task, provider/model, generated file bundle, exact failed command, and first failing stage.
   - Make the smallest patch in the MobiusX platform, apply it to a fresh generated reference project, and rerun affected checks.
4. **P0 exit gate.**
   - Frontend and backend build/start succeed.
   - Database initialization/migrations succeed.
   - Registration-to-manager-decision transaction persists and is visible in the UI.
   - Automated positive and negative workflow tests pass.
   - No unsupported claim of production readiness.

P1 orchestration, P2 UX, and P3 scale work remain deferred until the P0 exit gate is met.
