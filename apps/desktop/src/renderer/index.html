Settings

A terminal command guard (with an optional guarded hold-for-approval mode) and a secret scan on outbound task context, both with a shared audit trail. This is advisory, single-user governance — not enterprise policy management (no multi-tenant auth, no centrally-pushed org policy) and, for the terminal specifically, not a security sandbox: anyone with terminal access to this machine can bypass it. See docs/ARCHITECTURE.md §12 and the root README.

Command Guard (terminal — best-effort, reactive)

Terminal Approval (autonomy level)

"Off" is the reactive guard above: a flagged command still reaches the shell, then gets a best-effort Ctrl+C. "Guarded" catches a flagged command's Enter keystroke before it ever reaches the shell and holds it until you click Approve or Reject in the terminal panel. Same advisory caveat as above — this is not a security sandbox. Changing this only affects the terminal's next connection; use "Reconnect Terminal" below to apply it to the one currently open.
